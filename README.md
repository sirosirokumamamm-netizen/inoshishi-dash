# LASER SLICER / レーザー・スライサー

仕様書 v3.0 をもとにしたブラウザ向け物理パズルMVP。PCのマウスとスマートフォンのタッチ操作に対応しています。旧「イノシシダッシュ」に代わる新規実装です。

## 起動

Node.js 22.12以降（この環境では24.19）、npmを使用します。

```sh
cd /workspace/inoshishi-dash
npm ci --cache /tmp/laser-npm-cache
npm run dev
```

Viteの表示するアドレスで開きます。開発サーバーの標準ポートは5173です。バックエンド、APIキー、外部アセットサービスは不要です。欧文フォントを含むアセットはローカルから配信します。日本語は端末のフォントを使用します。

```sh
npm test          # 幾何計算・面積保存・Matter.js物理挙動：7件
npm run test:e2e  # Chromiumによる実操作テスト：8件
npm run build    # dist/ に静的サイトを生成
npm run preview  # 本番ビルドを確認
```

E2Eテストは、この環境の `/usr/bin/chromium` を自動利用します。他環境では `npx playwright install chromium` が必要です。ブラウザを取得する場合は `cdn.playwright.dev` などPlaywright公式ダウンロード先へのアクセスが必要になります。本環境では追加ダウンロードは不要です。

## 遊び方

1. 「プレイする」、またはステージを選択。
2. フィールド上でドラッグ／スワイプして照準、離すとレーザーを発射。
3. 小さい破片を消し、限られたショットで初期面積の80%以上を消去するとクリア。
4. 切断でゲージをため、パルスを起動して次のショットの連鎖ボーナスを強化。

`Esc` で一時停止・再開、`Space` でパルス起動。振動は対応端末のみ動作します。設定から音・振動・画面揺れ・パーティクルを個別に切り替えられます。画面揺れと粒子は、初回はOSの「視差効果を減らす」設定を尊重します。

## MVPで決めたルール

- スワイプ方向の直線を画面端まで延長。同じショットでは各オブジェクトを1回だけ切断します。
- 長さ24フィールド単位未満の操作・キャンセルはショットを消費しません。有効な空振りは消費します。
- 最初のブロックは固定。切られた大きな破片だけが落下し、衝突します。照準中は物理演算を止め、落下する破片を狙えるようにしています。
- 発射後は0.65秒（空振りは0.25秒）の待ち時間があり、そこでクリア・失敗を確定します。
- 消去判定は多角形の面積のみ。細長さによる自動消去はなく、画面外へ落として消去率を稼ぐこともできません。フィールドの床と壁で破片を保持します。
- 最大50物理破片・1系列8段階まで分割。上限に達する切断は適用せず、必要な面積を勝手に消しません。
- 1ショット内で2つ以上の破片が消えると連鎖。通常の切断でゲージを蓄積し、満タン時のパルスは次の1ショットの**連鎖ボーナスだけを2倍**にします。空振りでも発動権は消費します。
- 基本点：そのショットの消去面積 ÷ 初期総面積 × 10,000（四捨五入）。連鎖ボーナス：基本点 × (消去破片数の上限10 − 1) × 0.12（四捨五入）。クリア時は残りショット × 500点を追加。
- 95%以上で★3。80%以上かつ残り2ショット以上で★2。それ以外のクリアは★1。各ステージの最高点と最高評価を別々に保存します。
- 6ステージは最初から自由に選べます。記録は `localStorage` に保存し、保存が使えない場合もゲームは遊べます。

## 構成

- `src/geometry.js`：凸多角形の直線分割、面積、重心、照準線の延長
- `src/stages.js`：6ステージの形状・配置・消去閾値・ショット数
- `src/main.js`：ゲーム状態、Matter.js、Canvas描画、UI、Web Audio、保存
- `src/style.css`：PC／モバイル画面
- `tests/`：Node.jsテストとPlaywright実操作テスト

## 実装範囲と次の検証

タイトル、ステージ選択、プレイ、ポーズ、クリア、失敗、設定を実装済みです。テストでは実際の切断、面積消去、落下する大きな破片の再切断、クリア／失敗、再挑戦、保存、パルス、タッチ入力を確認しています。

実機Safari・Android Chromeでの音声／振動／性能、全ステージの難易度、30〜60秒に収まるプレイ時間は今後のユーザーテストで調整が必要です。物理演算は固定60Hzですが、異なる端末間での完全な結果一致は保証しません。

エンドレス、広告、課金、分析用データ収集、ネイティブアプリ化は未実装です。ユーザー情報を外部送信する処理はありません。

## GitHub Pagesへの公開

`.github/workflows/pages.yml` が `main` の更新時にテスト・ビルド・公開を実行します。相対アセットパスのため、リポジトリ名のサブディレクトリでも動作します。

初回のみ、GitHubのこのリポジトリで **Settings → Pages → Build and deployment → Source → GitHub Actions** を選択します。その後、**Actions → Deploy Laser Slicer to GitHub Pages → Run workflow** を実行してください。以後は `main` へのpushで更新されます。

公開先の予定URLは `https://sirosirokumamamm-netizen.github.io/inoshishi-dash/` です。デプロイ成功前には利用できません。公開状況はActionsの実行結果とSettings → Pagesで確認できます。
